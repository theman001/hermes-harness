## phase 1 종료의 정정 (중요)

워치독의 `attack_exhausted: true` 는 **실제 소진이 아니라 오판**이었다 — Round 2~4 동안
`web-페이지-구조.md`/`web-서버-구조.md` 를 갱신하지 않아 양축 `stale_rounds=3` 이 된 기계적
판정이었다. 라운드 예산(20)은 15개가 남아 있었다. phase 2 에서는 **매 라운드 구조 파일 2개를
갱신**하는 규율을 세웠고, phase 2 전 라운드에서 양축 해시가 바뀌어 오판이 재발하지 않았다.

## phase 2 에서 하지 않은 것 (사유 포함)

| 항목 | 사유 |
|---|---|
| `GET /<gid>/quitserver`, `/reset` | 무인증 DoS / 파괴적 DB 초기화 — 승인 필요 + 샌드박스 자산 손실, 권고하지 않음 |
| 타 계정 대상 무인증 `saveprofile`(`uid=cheddar`, `is_admin=True`) | 계정 경계를 넘는 상태변경. `uid` 가 계정을 정확히 겨냥함은 자기 계정 실험으로 이미 확인(타 계정 무변경) → 증거 중복이라 실행하지 않음 |
| 실제 관리자 동작(타 사용자 스니펫 삭제, `/reset`) | 파괴적 + 계정 경계 초과 → Round 9 는 관리자 **메뉴 렌더 + 소스 조건**으로 권한 획득을 닫음 |
| `secret.txt` 덮어쓰기 | 파일이 전 GID 공용이라 내 샌드박스 경계를 넘음 |
| 추가 읽기 IDOR(예: `editprofile.gtl?uid=<타인>`) | 이미 `dump.gtl` 로 전 DB 를 비인증으로 읽을 수 있어 심각도 변화 없음 |
