## 신규 절 — **쓰기 없는 재현 하네스** (`verify_chain.sh` 형태) ★

project 마감 시, 확정 취약점 전체를 **한 명령으로 다시 확인**하는 스크립트를 남긴다.
핵심 설계 원칙 세 가지:

1. **데이터를 바꾸지 않는다.** 재현 스크립트 자체가 공격 도구가 되면 안 된다.
   - 쓰기가 필요한 finding(임의 DML·저장형 XSS·second-order)은 **오라클/소스 조건으로만** 확인한다:
     · DML → `HAS_PERMS_BY_NAME(...'INSERT'/'UPDATE')` 같은 **권한 오라클**
     · 자격증명 → 값이 아니라 `CASE WHEN EXISTS(...) THEN 1 END` **읽기가능 오라클**
     · second-order → LFI 로 읽은 **소스에서 문자열 결합 지점** 존재 확인
     · 저장형 XSS → 대신 **쓰기 없는 반사 XSS**(세션명) 사용
   - 유일한 예외는 **거부되는 요청**(예: `PUT`) — 이 경우 "요청이 거부됨" + "대상 경로가 404(파일 미생성)"
     두 가지를 함께 검사해 **부작용이 없음**을 증명한다.
2. **각 항목에 부정 대조군을 함께 넣는다.** 체크가 "성공"만 세면 회귀를 못 잡는다:
   건수 비율로 판정(참 개수 > 0 && 거짓 개수 == 0), 열수 불일치 → 500, 부재 파일 → 500/404 등.
3. **결과를 PASS/FAIL 카운터로 출력하고 exit code 로 알린다.** 실패가 있으면 exit≠0 → CI 처럼 쓸 수 있다.

골격:

```bash
PASS=0; FAIL=0
chk(){      [ "$2" = "$3" ] && { echo "  PASS $1"; PASS=$((PASS+1)); } || { echo "  FAIL $1 기대=$2 실제=$3"; FAIL=$((FAIL+1)); }; }
chkhas(){   grep -qF -- "$3" "$2" && { echo "  PASS $1"; PASS=$((PASS+1)); } || { echo "  FAIL $1"; FAIL=$((FAIL+1)); }; }
q(){  # 모든 파라미터는 인코딩해서 GET (도구가 요청을 거부하는 함정 회피)
  local path="$1" out="$2"; shift 2; local a=(); for kv in "$@"; do a+=(--data-urlencode "$kv"); done
  curl -s --max-time 30 -o "$out" -G "${a[@]}" "$B$path"; }
# …항목별 체크…
printf 'PASS=%d FAIL=%d\n' "$PASS" "$FAIL"; [ "$FAIL" -eq 0 ] || exit 1
```

**스크립트에 반드시 넣을 메타 정보**
- 실행 시각(UTC)을 출력 — 결과는 **그 시각 기준**으로만 유효함을 명시.
- 상단 주석에 "데이터 변경 0건" 원칙과, 쓰기 항목을 오라클로 대체한 이유를 적는다.
- 대상/프록시를 환경변수로 교체 가능하게(`B=`, `P=`) 만들어 다른 환경에서도 재사용.

## 신규 절 — **불안정 대상에서의 증거 수명 관리** ★

이번 대상은 공개 데모라 **수 분 단위로 데이터가 변했다**(행 수 변동, 게시글 소멸 —
게다가 앱 자체가 `total>100 → DELETE` 로 게시판을 비우는 로직을 갖고 있었다).

- **행 수/ID 하드코딩 금지**: 카운트는 판정 근거가 아니라 **참고값**으로만 출력한다.
- **증거는 수집 시각과 함께** 파일로 고정(`evidence/`)하고, 요약 문서에는 "시각 기준 유효"를 명시.
- 재현 스크립트는 **매번 현재 값으로 재조회**하는 구조로 만든다(고정 ID 의존 금지).
- 게시글처럼 **소멸 가능한 증거**는 수집 직후 응답 원문을 복사해 두고, 이후 재조회 실패를
  "재현 실패"로 오독하지 않도록 일지에 경위를 적는다.

## 신규 절 — 정리 산출물과의 연결

- `verify_chain.sh` 는 `scripts/`(project 레벨)에 두고, 재현 근거 원문은 `evidence/`(INDEX 포함)에 둔다.
- `PoC-코드.md` 에는 **실행 확인분만** 싣고, 쓰기 필요한 항목에는 `[쓰기]` 표시와 ⚠️파괴적 분기 경고를 붙인다.
- 체이닝 서술에서는 **검증된 부분과 미검증 확장을 반드시 분리**한다(단정 금지).
